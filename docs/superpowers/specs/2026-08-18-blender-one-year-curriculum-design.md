# 一年份 Blender 每日學習計畫 — 設計規格

- 日期：2026-08-18
- 範圍：零基礎 → 一年內完成一隻可用於直播的 3D Vtuber 模型
- 狀態：設計定稿

## 1. 背景

使用者為 Blender 完全零基礎，目標是自製 3D Vtuber 模型。原本規劃走 AI 生成路線
（Tripo3D + Accurig + Blender + Faceit），參考 Nano（@Dstudio_ai, 2026-08-17）的流程。

該流程的實測結論是決定性的：作者自述「八成是 Blender 純人力作業」、「一半以上時間在刷權重」、
「撐不住鏡頭拉近」、「頭髮基本上不用想搖」。

**推論：AI 生成沒有繞過 Blender 技能，只是把門檻從「會建模」降到「會修模」。**
兩者都需要拓樸、UV、權重的實作能力。因此改為先建立技能基礎。

AI 生成（Tripo）不丟棄，降級為 P3/P4 的可選工具而非主線。

## 2. 目標與非目標

**目標**：一年後，使用者能獨立產出一隻 VRM 模型，在既有的 `~/Repos/VtuberProject`
（Unity 6 + URP + NiloToon + iFacialMocap）中被 iPhone 臉部追蹤驅動。

**非目標（YAGNI）**：
- 成為專業角色建模師
- 涵蓋 Blender 全部功能（幾何節點、模擬、影視算圖等一律不教）
- 寫實風格建模（只走動漫/卡通向）
- 一次寫死全部 312 天的任務內容

## 3. 關鍵約束

| 約束 | 內容 | 對設計的影響 |
|---|---|---|
| 時間 | 每日 30–60 分鐘 | 全年約 200–250 小時。落在業界估計（150–400 小時）區間內，但無餘裕 |
| 跨 session | 每次對話是全新的 Claude，無昨日記憶 | 狀態必須完全外部化；任務必須自足 |
| 無畫面 | Claude 看不到使用者螢幕 | 驗收改用 headless Blender 檢查 `.blend` 檔 |
| 會請假 | 使用者明確表示有些天做不了 | 進度以「完成的任務數」計，非日曆天 |

## 4. 階段結構

一週排 6 天，第 7 天彈性（補課或休息）。全年約 **312 個任務日**。

| 階段 | 天數 | 內容 | 畢業驗收 |
|---|---|---|---|
| P1 基礎 | Day 1–60 | 介面、導航、修改器、材質、燈光、算圖 | 不看教學，獨立做出非指定小物件並算圖 |
| P2 建模紮實化 | Day 61–150 | Box modeling、有機建模、**拓樸**、retopology、UV、貼圖 | 拓樸乾淨的頭部（非最終角色） |
| P3 角色建模 | Day 151–240 | 人體比例、動漫頭身、頭髮、服裝、眼睛 | 原創角色完整 mesh |
| P4 Vtuber 化 | Day 241–312 | 骨架、權重、ARKit 52 shape key、搖物、VRM、Unity 整合 | 在 `VtuberProject` 中被 iPhone 驅動 |

### 三個刻意的設計決定

1. **最終角色到 P3 才開始，P1–P2 產出全部拋棄式。**
   零基礎第一次做的一定會爛。常見失敗模式是第一個月就開始做「我的角色」，
   然後捨不得重練，抱著歪掉的基礎硬走一年。

2. **P2 花 3 個月在拓樸。**
   Nano 遭遇的所有痛苦（權重難刷、頭髮不能搖）根源都是拓樸。
   這是唯一沒有捷徑、AI 也繞不過的部分。

3. **畢業標準綁在既有的 `VtuberProject` 上**，而非抽象的「學會 Blender」。
   P4 驗收可執行：模型載入 → iFacialMocap 驅動 → NiloToon 呈現。

## 5. 教材策略（混合）

| 階段 | 來源 |
|---|---|
| P1 | Blender Guru「Donut 5.0」系列 → Blender 5.0 完整初學課程（免費，與 Blender 5.x 版本相符） |
| P2 | 現成教材 + 自訂練習漸增 |
| P3 | 以自訂為主（動漫向教材缺口，見風險） |
| P4 | 全自訂（無現成教材涵蓋 Blender → VRM → ARKit 52 → NiloToon 完整鏈路） |

**教材綁定原則**：任務不寫死「Part N 的 12:30」，改以**主題 + 驗收條件**描述。
教材更新不影響課程有效性。

## 6. 跨 Session 運作機制

```
ProjectVtuber/
├── CLAUDE.md              每 session 自動載入的操作規則
├── curriculum/            唯讀：課程內容
│   ├── overview.md
│   └── p1-foundations.md
├── progress/
│   ├── STATUS.md          ★ 單一真相來源
│   └── log/YYYY-MM-DD.md  每日記錄，追加式
├── tools/inspect_blend.py 驗收腳本
└── work/p1..p4/           使用者的 .blend 檔
```

- **`STATUS.md` 為唯一真相來源。** 新 session 只讀此檔即可得知：目前第幾天、上次卡在哪、待補項目。
- **Day N = 完成的第 N 個任務，非日曆第 N 天。** 請假只推遲終點，不製造「落後」。
  連續打卡制的失敗模式是斷一天即整體放棄，而一年計畫斷線是必然。
- **`curriculum/` 唯讀、`progress/` 可寫**，避免課程與進度互相污染。
- **每日任務格式固定且自足**：主題 → 教材 → 動手 → 驗收條件 → 存檔位置。

## 7. 驗收機制

`tools/inspect_blend.py` 以 headless Blender 執行，回報：
頂點/面數、三角面與 n-gon 數、UV 層與重疊、材質、骨架階層、shape key 名稱與數量、修改器堆疊。

已實測可行（Blender 5.2.0 Alpha 回報預設方塊資料正確）。

意義：「做完了」可被客觀檢查，而非自由心證。對零基礎特別重要——
初學者最常見的問題是「自以為做對了，其實一開始就歪了」。

## 8. 教學節奏：學 → 消化

P1 採「學一天、消化一天」的交替節奏。消化日的內容是**不看教學重做前一天的成果**。

理由：跟著影片操作只證明「能跟上」，不證明「會做」。消化日是把觀看轉換成能力的關鍵環節，
也是唯一能在早期就抓出「其實沒學會」的機制。

## 9. 範圍控制

**只先寫 P1 的 60 天細節，P2–P4 僅留大綱。**

理由：(a) 實際進度必然偏離預期；(b) P3/P4 的教法取決於 P1/P2 的真實表現。
現在寫死 312 天，大部分會作廢。各階段接近時再細化。

## 10. 風險

| 風險 | 影響 | 緩解 |
|---|---|---|
| 動漫向教材缺口 | 英文 Blender 教材多為寫實向，動漫角色在拓樸、比例、眼睛結構上是另一套技法 | P3 前評估日文圈教材；必要時由 Claude 自訂補上。**尚未解決** |
| Blender 版本 | 目前安裝為 5.2.0 Alpha，UI 會變、addon 會壞 | 開始前換正式版並記錄版本號至 STATUS.md |
| 中途放棄 | 一年計畫的主要失敗模式 | Day N 不綁日曆；彈性日；階段性可見成果 |
| 時數不足 | 200–250 小時落在估計區間下緣 | P1–P2 嚴格控制範圍，不教用不到的功能 |
| Faceit 相容性 | P4 需要，付費 addon，對 Blender 5.x 支援未確認 | P4 前確認；備案為手工建立 ARKit 52 shape key |

## 11. 成功標準

1. 使用者能在 Blender 中從零建出一個動漫角色 mesh，拓樸可用於形變。
2. 該模型完成綁骨、權重、ARKit 52 shape key、搖物設定。
3. 匯出 VRM，於 `VtuberProject` 中載入，由 iPhone iFacialMocap 驅動臉部與頭部，NiloToon 正常呈現。
4. 上述由 `inspect_blend.py` 與 Unity 實機驗證，非自由心證。
